# L-science 实施计划

任务按分期路线组织。每条任务标注它满足的需求编号（对应 `requirements.md`）。

约定：

- 每条任务都必须以「可运行、可验证」结束，不留半成品接口。
- 原生依赖一律用 prebuilt，禁止引入需要 node-gyp 现场编译的包（需求 20.1）。
- 后端包的相对导入写 `.js` 后缀；UI 包走 bundler 解析用无扩展名。
- 新增或修改行为时同步补测试，测试与实现在同一条任务内完成。

## M1 执行平面

### 2. 控制平面与渲染层的传输通道

- [x] 2.1 定义 IPC 契约与错误信封
  - 在 `@l-science/shared` 增加请求/响应/事件三类消息的判别联合类型，含关联 id 与错误信封（错误码 + 用户可读消息 + 是否可重试）
  - 用 zod 定义运行期校验 schema，导出类型由 schema 推导，避免类型与校验漂移
  - `isRetryable` 由错误码决定且不接受调用方覆盖；`content_filtered` 与 `policy_denied` 永不可重试
  - `parseFrame` 先按 `type` 分派再校验：直接喂 union 时 zod 只在根节点报泛化错误，定位不到出问题的字段
  - 测试：非法载荷被拒且错误码正确
  - _需求：1.3_
- [x] 2.2 后端传输层与请求分发
  - 在 `@l-science/core` 实现基于换行分隔 JSON 的 stdio 传输，供 Electron main 与后端进程通信；实现请求路由、并发请求关联、事件广播
  - 刻意不开 TCP 端口：M1 阶段没有跨机需求，stdio 天然避免了本机多用户下 localhost 不可信的问题
  - `LineDecoder` 遇超长帧时清空缓冲并跳到下一个换行符，保证一个巨型帧只损失它自己
  - 处理器抛出的任何东西都被转成错误信封，单个坏请求不能拖垮传输循环
  - **后端日志一律走 stderr**：stdout 被协议通道独占，写一行普通文本就会让对端解析失败
  - 测试：并发请求各自拿到正确响应；事件不丢；载荷超限被拒
  - 端到端：`npm run verify:backend`（10 项，含 stdout 洁净性与 stdin EOF 自退出）
  - _需求：20.3.3_
- [x] 2.3 Electron main 的 IPC 桥与 preload 窄接口
  - main 侧把渲染层的 `invoke` 转发给后端进程并把后端事件推给渲染层；preload 只暴露具名方法，不暴露 `ipcRenderer`
  - `BackendClient` 只依赖 `@l-science/shared`，不碰 core，从而让 Electron 侧永远不引入原生模块
  - 修正 main 进程原先用 `stdio:['ignore',...]` 启动后端的问题：stdin 被忽略会让后端立刻收到 EOF 并自退出
  - 测试：17 条协议客户端测试，覆盖响应关联、超时不泄漏 pending、后端退出拒绝在途请求、stdout 非协议内容不当作帧
  - _需求：5.1（进程边界部分）_
- [x] 2.4 渲染层连接与事件消费
  - React hook 封装请求与事件订阅，带上界的指数退避重连；收到后端退出日志时立即重连
  - 错误码从主进程编码的 message 中还原为结构化错误，供 UI 按码决定行为（如 `policy_denied` 不显示重试）
  - _需求：20.2.1、20.2.2_
