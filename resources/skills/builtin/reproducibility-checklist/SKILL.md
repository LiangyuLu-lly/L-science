# 可复现性清单

## 判据

只有一条：**一台干净的机器 + 你提供的材料，能不能得到同样的数字？**

「同样」的标准要分清：

- **可复现（reproducible）**：同数据 + 同代码 → 同结果。这是底线，做不到就是缺陷。
- **可重复（replicable）**：新数据 + 同方法 → 同结论。这是科学目标，不是单篇论文的责任。

下面全部针对第一条。

## 逐项清单

### 数据

- [ ] 原始数据有唯一标识与版本（哪次导出、什么时候）。
- [ ] 从原始数据到分析数据的每一步都有代码，**没有手工在 Excel 里改过的中间文件**。
- [ ] 排除的样本有记录：排除了谁、为什么、在哪一步。
- [ ] 数据字典：每一列的含义、单位、取值范围、缺失编码。

手工修改是可复现性的头号杀手，因为它不留痕迹。**任何「我在 Excel 里改了一下」
都要改写成代码。**

### 代码

- [ ] 每个图表都能由代码从分析数据重新生成（平台的制品血缘会检查这一点）。
- [ ] 随机种子固定并记录（`np.random.default_rng(42)`、`random_state=42`、
      `torch.manual_seed(42)`、R 的 `set.seed(42)`）。
- [ ] 没有硬编码的绝对路径（`C:\Users\...`）。用相对路径或配置。
- [ ] 执行顺序明确：一个入口脚本，或编号的脚本，或 Makefile。
      「先跑 a 再跑 c 再跑 b」这种隐式依赖必须写出来。

### 环境

- [ ] 记录了完整的包版本，不只是主要的几个：

```python
# Python
import subprocess, sys
subprocess.run([sys.executable, '-m', 'pip', 'freeze'],
               stdout=open('requirements-lock.txt', 'w'), check=True)
```

```r
# R
writeLines(capture.output(sessionInfo()), 'sessionInfo.txt')
# 或用 renv：renv::snapshot()
```

- [ ] Python 与 R 的**主版本号**在方法里写明。
- [ ] 关键库的版本在方法里写明（MNE、YASA、statsmodels、sklearn……）。
      不同版本的默认参数会变，这是「代码没改结果变了」的常见原因。

### 统计

- [ ] 模型公式原样写出（含随机效应结构）。
- [ ] 多重比较校正的方法与家族写明。
- [ ] 预注册与实际分析的差异逐条说明。**偏离预注册不是问题，不说明才是问题。**
- [ ] 探索性分析明确标注。

### 血缘

- [ ] 每张图、每张表都能追溯到：生成代码 + 输入数据版本。
- [ ] 论文里的每个数字都能追溯到某个制品。

平台会在保存制品时检查这一点：**图有代码但没有输入数据版本，仍会被标记为血缘不完整**
——因为「代码里的数据来源不明」意味着别人跑不出同样的图。

## 归档

投稿时至少准备：

```
data/                原始数据（或获取说明）
  raw/               不可修改
  derived/           由代码生成，可删可重建
code/
  00_ingest.py       编号说明执行顺序
  01_preprocess.py
  02_analysis.py
  03_figures.py
env/
  requirements-lock.txt
  sessionInfo.txt
  environment.yml
README.md            怎么从零跑一遍，预计耗时
```

README 里必须有**「从零跑一遍」的完整命令序列**与预计耗时。缺这一项，
别人拿到仓库第一步就卡住。

## 数据不能公开时

不公开数据不影响其他各项。仍然要提供：

- 代码（完整，不删减）。
- 数据字典与合成/去标识的示例数据（能跑通代码，验证代码本身没问题）。
- 数据申请途径（见 `data-availability-statement`）。

**「数据不能公开所以代码也不给」是站不住的。** 代码是方法的一部分。

## 自查方法

最有效的一步：**在一个新的空目录里，只用归档包，从头跑一遍。**

常见失败：路径写死、依赖某个只在你机器上的文件、依赖某个已被你手动改过的中间产物、
依赖某个未记录的环境变量。这些问题只有真跑一遍才会暴露——通读代码发现不了。
