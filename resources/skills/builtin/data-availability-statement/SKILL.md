# 数据可得性声明

## 先确定实际状况

写声明之前必须先回答四个问题，答案决定用哪个模板：

1. 数据能公开吗？（伦理批件与知情同意书里怎么写的？）
2. 去标识后能公开吗？（PSG 原始信号是否属于可识别信息，各地法规不同）
3. 代码能公开吗？（几乎总能，且应当公开）
4. 有没有第三方数据？（其许可条款怎么规定的）

**不要先写声明再倒推。** 知情同意书里没有「数据可能被公开共享」这一条时，
公开数据是违规的——这个约束在研究设计阶段就该考虑，到投稿时已经无法补救。

## 完全公开

```
支持本研究结论的数据与分析代码已存放于 Zenodo（DOI: 10.5281/zenodo.XXXXXXX）。
仓库包含去标识的多导睡眠图导出数据、预处理与统计分析的完整代码，
以及重现全部图表所需的脚本。
```

仓库选择：

| 仓库 | 适用 | 特点 |
|---|---|---|
| Zenodo | 通用，含代码 | 免费、有 DOI、支持大文件、与 GitHub 联动打版本 |
| OSF | 含预注册的项目 | 可关联预注册、支持版本 |
| figshare | 图表与补充材料 | 有 DOI |
| Dryad | 数据（收费） | 与多家期刊有集成 |
| OpenNeuro | 神经影像与电生理 | BIDS 规范，领域专用 |
| PhysioNet | 生理信号 | 领域专用，有审核流程 |

**必须给 DOI 而不是 GitHub 链接。** GitHub 仓库可以被删除、改名、force push，
不是持久标识。做法是把 GitHub 仓库通过 Zenodo 打一个版本快照，引用那个 DOI。

## 受限访问

```
由于知情同意条款限制，个体层面的多导睡眠图数据不可公开。
去标识数据可经{机构}数据访问委员会审批后获取，申请途径为 {URL 或邮箱}，
申请需提交研究方案并签署数据使用协议。汇总层面的数据
（各被试的睡眠指标）与全部分析代码已公开于 Zenodo（DOI: ...）。
```

三个要点：**具体的申请途径、明确的审批主体、以及能公开的那部分要真的公开。**

## 完全不能公开

```
由于{具体原因：知情同意条款 / 涉及可识别的临床信息 / 第三方数据许可限制}，
本研究数据不可公开共享。全部分析代码已公开于 Zenodo（DOI: ...），
并附合成示例数据以便验证代码可执行。数据字典见补充材料表 S1。
```

**「数据不公开所以代码也不给」是站不住的。** 代码不含被试信息，
它是方法描述的一部分。审稿人与读者有理由要求它。

## 避免的写法

**「数据可应合理要求向通讯作者提供」**——这是最常见的写法，但方法学研究反复表明
它的实际兑现率很低（多数请求得不到回应或被拒）。越来越多期刊不再接受它作为唯一途径。

如果确实只能走这条路，至少写清：谁负责、以什么形式提供、需要什么条件、
预计多久回应。

## 第三方数据

用公开数据集时要给出获取途径与版本，并遵守其引用要求：

```
本研究使用 Sleep-EDF Database Expanded（版本 1.0.0，PhysioNet，
https://doi.org/10.13026/C2X676）。按该数据集要求，我们引用了
Kemp 等（2000）与 Goldberger 等（2000）。分析代码见 Zenodo（DOI: ...）。
```

**数据集版本号必须给。** 公开数据集会更新（增删被试、修正标注），
没有版本号别人复现时可能拿到不同的数据。

## 代码可得性单独声明

部分期刊要求代码与数据分开声明：

```
代码可得性：预处理、统计分析与图表生成的全部代码已公开于
Zenodo（DOI: ...），使用 MIT 许可。运行环境（Python 3.13、MNE-Python 1.12.1、
YASA 0.7.0 等完整版本清单）见仓库内 requirements-lock.txt。
```

选一个明确的许可（MIT、BSD-3、Apache-2.0）。**没有许可的代码在法律上是不可复用的**
——别人不敢用，等于没公开。

## 与其他声明的关系

数据可得性声明经常与下列声明相邻，一起核对（见 `journal-templates` 的清单）：
伦理批准、知情同意、利益冲突、资助、作者贡献（CRediT）、预注册号。
