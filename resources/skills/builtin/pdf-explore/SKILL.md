# PDF 深读

## 不要整篇读进上下文

一篇 20 页的论文是 6-10 万字符。整篇塞进上下文会挤掉对话历史与其他材料，而任何一次
提问真正需要的通常是一两段。

用 `read_file` 的 `page` 参数按页读：

```
read_file(versionId=<制品版本 id>, page=1)     # 先读第 1 页：标题、摘要、关键词
```

## 定位策略

按目的直接跳到对应部分，而不是从第 1 页顺序读：

| 想知道 | 去哪 |
|---|---|
| 做了什么、结论是什么 | 摘要（第 1 页） |
| 样本量、纳入排除、设备与参数 | Methods（通常第 2-4 页） |
| 具体数值、统计量 | Results + 表格 |
| 局限与适用范围 | Discussion 末段 |
| 数据与代码在哪 | Data Availability（常在末页或摘要后） |
| 利益冲突与资助 | 末页 |

先读摘要，从摘要判断需不需要往下读——这一步能省掉大部分无关文献的深读。

## 摘要之后的第一件事：核对适用范围

提取任何数值之前先确认三要素，否则提出来的数字可能根本不适用：

- **人群**：年龄范围、临床诊断、性别构成。
- **干预/暴露**：具体是什么、剂量、时长。
- **结局指标**：定义与测量方式（TST 是 PSG 测的还是自报的？）。

这三项在 Methods 的第一两段。它们不匹配时，后面的数值再准确也用不上。

## 提取数值的纪律

每一个提取出的数值都要带三样东西：

```python
extracted = {
    'value': 38.2,
    'unit': '%',
    'what': '老年组慢波活动相对于青年组的下降幅度',
    'page': 4,
    'quote': 'SWA was 38.2% lower in the older group (p < .001)',   # 原文，≤30 词
    'source_version_id': '<制品版本 id>',
}
```

**页码与原文引句不是可选的。** 没有它们，这个数字在半年后无法追溯，
而审稿人问「这个 38% 是从哪来的」时你需要立刻能指出位置。

如果一个数只出现在图里、正文没写，**不要目测读数**。写「文中未给出具体数值，
图 3 显示约 38%（目测）」并标注为估计值。目测读图的误差在对数坐标或误差棒重叠时很大。

## 表格

PDF 里的表格经文本抽取后列会错位。可用做法：

1. 先按页读出文本，看结构是否可辨。
2. 结构乱掉时用 Python 做结构化抽取：

```python
# pdfplumber 对有线框的表格效果较好
import pdfplumber
with pdfplumber.open(path) as pdf:
    tables = pdf.pages[3].extract_tables()
```

3. 抽取结果**必须与 PDF 目视核对至少两行**。表格抽取错位是静默的：数字都在，
   只是配错了行列，而这类错误看输出完全发现不了。

没装 pdfplumber 时，把该页文本原样保留并手工读出需要的单元格，别让程序猜。

## 补充材料

方法细节（预处理参数、检索式、逐项结果）经常只在补充材料里。正文找不到时：

- 看 Data Availability 与 Supplementary 的链接。
- 补充材料往往是独立 PDF/Excel，要单独获取（见 `literature-search` 的抓取部分）。

正文没有而补充材料里有的信息，引用时要注明「见补充材料表 S2」。

## 存成制品

把「从这篇文献提取了什么」存成结构化制品，与 PDF 制品建立血缘：

```python
save_artifacts(paths=['extraction_smith2019.json'],
               code=..., inputVersionIds=['<PDF 的制品版本 id>'])
```

这条血缘边的价值在于：日后发现某篇文献被撤稿或有更正时，能立刻查出哪些结论依赖它。
